# 言語固有の観点: TypeScript

以下はTypeScript固有の欠陥パターンと設計観点である。コアプロンプトの共通観点に加えて、これらを分析に適用すること。

## 型安全性の欠陥

- **any型の乱用**: `any` は型チェックを完全に無効化する。外部入力には `unknown` を使い、型ガードで安全に絞り込む
- **as キャストの乱用**: 型アサーション (`as`) はコンパイラの型チェックを上書きする。Zod等のバリデーションライブラリで型を確定させる
- **型ガードの欠如**: union型やnullable型をオプショナルチェーン (`?.`) で安易に回避するパターンは潜在的バグを隠蔽する。カスタム型ガード関数で明示的に処理する

## カプセル化の欠陥

- **interface と type の不適切な使い分け**: `interface` は拡張・実装されるオブジェクト型、`type` はunion/intersection/タプル/マップ型に使用。`enum` より文字列リテラルunionを優先
- **エクスポートされた関数の型宣言欠如**: 公開APIには明示的な型宣言が必要。内部のローカル変数は推論に任せてよい
- **ジェネリクスパターンの欠如**: 同じ構造の型を複数定義するのは型の再利用性を損なう。`ApiResponse<T>` や `Repository<T>` のようなジェネリクスで一貫性と再利用性を高める

## 不変性の欠陥

- **ミュータブルな操作**: オブジェクトや配列を直接変更するとバグの原因になる。スプレッド構文でイミュータブルに更新する
- **Readonly<T> の未活用**: 変更しない引数には `Readonly<T>` を付けてコンパイラレベルで変更不可を保証する。特に関数引数、DI依存、React propsで欠落を検出
- **Partial/Required の過剰使用**: ユーティリティ型の過剰使用は型の意図を不明確にする。目的に応じた明示的な型定義を優先

## 関心の分離の欠陥

- **React Props の型定義不備**: `React.FC` の使用（暗黙的な副作用あり）、propsの型なし、コールバックpropsの `Function` 型は欠陥。`interface XXXProps` で名前付き型を定義する
- **React コンポーネントの肥大化**: UIレンダリング、状態管理、API通信が1コンポーネントに混在。カスタムフックで関心を分離する

## セキュリティの欠陥

- **シークレットのハードコード**: APIキーやトークンの直接記述。環境変数を使用すべき
- **未検証の外部入力**: APIレスポンスやユーザー入力を型アサーションで信頼。Zodなどでバリデーションすべき
- **XSS**: `dangerouslySetInnerHTML` の安易な使用
- **console.log の残存**: 本番コードでのデバッグログ残存。適切なロガーを使用すべき

## その他の欠陥パターン

- **非同期処理のエラー未処理**: `Promise` の `.catch()` 欠如、try-catchなしのawait
- **コールバック地獄**: async/awaitで置き換え可能なネストしたコールバック
- **暗黙的な型変換**: `==` の使用（`===` を使うべき）
- **未使用のインポート**: バンドルサイズの増大とコードの可読性低下
