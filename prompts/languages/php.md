# 言語固有の観点: PHP

以下はPHP固有の欠陥パターンと設計観点である。コアプロンプトの共通観点に加えて、これらを分析に適用すること。

## 型安全性の欠陥

- **strict_types 宣言の欠如**: `declare(strict_types=1)` がないファイルではPHPの暗黙的型変換により予期しない動作が発生する
- **型宣言の欠如**: 引数・戻り値・プロパティに型宣言がないコードはカプセル化とドメインモデルの完全性を損なう
- **mixed型・union型の乱用**: `mixed` や過剰なunion型は型安全性を破壊する。境界で型を確定させる

## カプセル化の欠陥

- **publicプロパティの乱用**: データとロジックの分離を招く。readonlyプロパティまたはgetterを使用し、ビジネスルールをカプセル化する
- **サードパーティSDKのアダプター未使用**: 外部SDKをアダプタークラスで包まず直接依存すると、SDK変更がビジネスロジック層にまで波及する。インターフェースで抽象化し依存を閉じ込める
- **連想配列の乱用（DTOの欠如）**: ビジネスデータを連想配列で持ち回すとキー名の不整合やバリデーション漏れが発生する。`final readonly class` でDTOを定義する

## 不変性の欠陥

- **readonlyの未活用**: PHP 8.1+ の `readonly` プロパティ、PHP 8.2+ の `readonly class` で値オブジェクトやDTOを不変にすべき。変更が必要な場合は新しいインスタンスを返す

## セキュリティの欠陥

- **SQLインジェクション**: 文字列結合によるSQL構築。プリペアドステートメントを使用すべき
- **mass assignment**: Eloquentの `$fillable` / `$guarded` の未設定
- **シークレットのハードコード**: APIキー・パスワードの直接記述。環境変数を使用すべき
- **CSRF保護の欠如**: 状態変更リクエストにCSRFトークン検証がない
- **パスワード管理**: `password_hash()` / `password_verify()` を使用していない
- **出力エスケープの欠如**: テンプレートの出力はデフォルトでエスケープすること。Bladeなら `{{ }}` を使用。`{!! !!}` は正当な理由がある場合のみ。エスケープ欠如はXSSに直結
- **セッションID再生成の不備**: 認証処理や権限変更後にセッションIDを再生成していないコードはSession Fixation攻撃のリスク。`$request->session()->regenerate()` を使用する

## その他の欠陥パターン

- **`false`/`null` をエラーチャネルとして返す**: エラー発生時に `false` や `null` を返すと呼び出し元でのエラー処理が漏れやすい。例外で明示的に通知すること
- **ファイル末尾の `?>`**: 終了タグ以降の空白がHTTPヘッダーエラーやJSONパース失敗の原因になる
- **リファレンス `&` の多用**: PHPはCopy-on-Writeを採用しており、不要なリファレンスは可読性と安全性を低下させる
- **`namespace` を利用しない**: グローバル名前空間にクラスを配置すると名前衝突のリスクが高まる
- **staticメソッドの過剰使用**: テスト時のモック化が困難で暗黙的な依存関係を生む。依存注入を優先する
