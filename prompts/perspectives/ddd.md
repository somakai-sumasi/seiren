# 追加の設計観点: DDD (Domain-Driven Design)

以下の観点も考慮して分析してください：

## DDDの主要概念
- **エンティティ**: 同一性を持つオブジェクト
- **値オブジェクト**: 同一性を持たない、属性で定義されるオブジェクト
- **集約**: トランザクション境界を持つエンティティのクラスタ
- **リポジトリ**: 集約の永続化を抽象化
- **ドメインサービス**: エンティティや値オブジェクトに属さないドメインロジック

## DDD観点での欠陥パターン
- エンティティが値オブジェクトとして扱われている
- 集約境界を越えた直接参照
- リポジトリがドメインロジックを持っている
- ユビキタス言語の不在（技術用語のみの命名）

## 改善の方向性
- プリミティブ型を値オブジェクトに置き換え
- ビジネスロジックをエンティティ/値オブジェクトに移動
- 集約の境界を明確化
- ユビキタス言語を反映した命名

## 推奨パターン
- Value Object: 不変、等価性で比較
- Entity: 同一性で識別、状態遷移のメソッドを持つ
- Aggregate Root: トランザクション境界、不変条件の保護
- Domain Service: エンティティに属さないドメインロジック
