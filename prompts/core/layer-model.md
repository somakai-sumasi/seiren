## Model層（ドメインモデル）の責務定義

### 定義

Model層とは、ビジネスドメインの概念・ルール・振る舞いを表現するオブジェクト群の層である。
アプリケーションが扱う「問題領域そのもの」をコードで表現する責務を持つ。

Model層は以下の構成要素から成る:

1. **エンティティ（Entity）**
   - 同一性（Identity）によって識別されるオブジェクト
   - ライフサイクルを持ち、状態が変化しても同一性は保たれる
   - 自身の不変条件（invariant）を常に満たす責務を持つ
   - 例: ユーザー、注文、商品

2. **値オブジェクト（Value Object）**
   - 同一性を持たず、属性の等価性によって比較されるオブジェクト
   - 不変（immutable）であること
   - 自身の値に対するバリデーションとドメインロジックをカプセル化する
   - 例: 金額、メールアドレス、住所、期間

3. **集約（Aggregate）**
   - トランザクション整合性の境界を定義するエンティティのクラスタ
   - 集約ルート（Aggregate Root）を通じてのみ外部からアクセスされる
   - 集約内の不変条件を保護する

4. **ドメインイベント（Domain Event）**
   - ドメインにおいて発生した出来事を表現するオブジェクト
   - 不変であり、過去に起きた事実を記述する

### Model層が持つべき責務

- ビジネスルールの実装（条件判定、状態遷移、計算ロジック）
- 自身の不変条件の保護（コンストラクタ・ファクトリメソッドでのバリデーション）
- ドメイン用語（ユビキタス言語）を反映した命名
- 他のドメインオブジェクトとの関係性の表現

### Model層が持ってはいけない責務

- 永続化処理（SQLの発行、ファイルI/O）
- HTTPリクエスト/レスポンスの処理
- フレームワーク固有の機能への依存
- 外部サービスへの通信
- トランザクション管理
- 認証・認可の制御（ポリシー判定のためのデータ提供は可）

### 判断基準

1. **ビジネスロジックの所在**
   - ビジネスルール（条件判定、計算、状態遷移）がModel内に実装されているか
   - Service層やController層にビジネスロジックが漏れ出ていないか
   - getter経由でデータを取り出し外部で計算・判断していないか

2. **不変条件の保護**
   - 不正な状態のオブジェクトが生成されない構造になっているか
   - publicなsetterにより外部から状態を自由に変更できてしまわないか
   - コンストラクタまたはファクトリメソッドで入力値のバリデーションが行われているか

3. **値オブジェクトの活用**
   - プリミティブ型（string, int, float）がドメイン概念の代わりに使われていないか
   - 意味のある単位（金額、メールアドレス、識別子等）が値オブジェクトとして表現されているか
   - 値オブジェクトが不変であるか

4. **ドメイン知識の表現**
   - クラス名・メソッド名・変数名がビジネスドメインの用語を反映しているか
   - 暗黙のビジネスルールがコメントではなくコードで表現されているか
   - Enumや定数がドメイン概念を適切に表現しているか

5. **依存の方向**
   - Model層がインフラ層（DB、外部API、フレームワーク）に依存していないか
   - Model層が他のどの層にも依存せず、最も内側に位置しているか

6. **永続化モデルとの分離**
   - ORMのモデル（Eloquent Model等）がドメインモデルの代わりに使われていないか
   - 永続化の都合（テーブル構造、カラム名）がドメインモデルの設計に影響していないか
   - ドメインモデルがORMのアノテーションやトレイトに依存していないか

### 欠陥パターン

- **貧血ドメインモデル（Anemic Domain Model）**: getter/setterのみでビジネスロジックを持たないModel。ロジックがService層に流出し、Modelが単なるデータ構造体になっている
- **プリミティブ型執着（Primitive Obsession）**: 金額をint、メールアドレスをstringで扱い、バリデーションや振る舞いがModel外に散在する
- **ORMモデルのドメインモデル兼用**: Eloquent ModelやDoctrineエンティティをそのままドメインモデルとして使用し、永続化の関心とビジネスロジックが混在する
- **不変条件の未保護**: publicなsetterやプロパティにより、オブジェクトが不正な状態に遷移可能になっている
- **集約境界の不在**: エンティティ間の直接参照が無制限に行われ、トランザクション整合性の境界が不明確
- **ドメイン知識の暗黙化**: ビジネスルールがif文のネストやマジックナンバーで実装され、ドメイン概念として命名されていない
- **Modelからのインフラ依存**: Model内でDBアクセスや外部API呼び出しを行っている
